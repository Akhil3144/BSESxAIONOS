# Historical blind testing and leakage boundary

Original proposal §§7.1/8.2 requires independently selected 8–12 eligible historical cases, a jointly frozen selection/rubric, withheld final awards until prediction, retained failures/variance/reviewer objections and BSES defensibility review. The code demonstrates this with ten synthetic holdouts; it does not establish independent business acceptance.

Holdout awards are separate from source records. Generic reference import uses an allowlisted schema and detects outcome/award/negotiated/final-price/holdout names case-insensitively. Unmapped/outcome-bearing files are rejected with HTTP 422 **before storing original bytes or rejected-row payloads**, preventing a rejected holdout file from being retrievable through general evidence access. Ordinary invalid prices/dates are still logged with their raw values. Approved historical outcome records require a future controlled projection workflow; generic award imports are intentionally not enabled.

Predictions read only holdout quote and ID. Reference selection removes explicit holdout IDs/source refs and excludes own/same procurement_event_id, transaction dates on/after quote, and optional available_date on/after quote. Unknown optional metadata is not accepted into new reference imports. No index/FX/derived-market adjustment is used, so those routes cannot silently introduce future fitted values. General dashboard activity exposes event metadata only, never audit payloads containing revealed award values.

A verified source snapshot and fully resolved active policy are frozen into every evaluation rubric and prediction, together with the prediction SHA256. There is no prediction-edit endpoint. Evaluator/admin reveal only after persistence and hash verification; reveal is idempotent. Results include coverage, absolute percentage error versus unrounded-derived target display, band-to-award variance, comparator counts/lineage failures and reviewer findings. Findings are editable through audited reviewer/evaluator/admin actions without altering locked predictions.

The final source authenticity and semantic leakage boundary remains human: an award disguised as a normal unit price or incorrect availability date/event ID cannot be detected reliably by field rules alone. Source-code/database administrators can read synthetic outcomes and are outside the evaluator threat boundary. No claim is made that the synthetic seed is unknown to developers. Real holdouts require independently controlled source curation, availability/effective-date review, approved minimums and errors, source ownership and SME acceptance. Failed/outlier cases stay visible; software tests cannot approve business thresholds.
